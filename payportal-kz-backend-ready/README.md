# PayPortal KZ — толық сайт + Node.js төлем интеграциясы

Бұл ZIP екі мақсатқа арналған:

1. **Сайттың толық дизайнын көрсету:** ZIP түбірінде `index.html` бар, ал жариялауға арналған дайын статикалық нұсқасы `dist/` ішінде.
2. **Backend-пен іске қосу:** `server.js` `public/` ішіндегі сол беттерді серверден береді және API маршруттарын іске қосады.

## Не бар

- Қазіргі responsive дизайн және ортақ навигация.
- Басты бет, Мүмкіндіктер, Әзірлеушілерге, Төлем статусы, Әкімші панелі, Төлем нәтижесі, Пайдалану шарттары, Құпиялық және 404 беті.
- Freedom Pay hosted-checkout үшін backend сұрауының құрылымы.
- Provider result callback қолтаңбасын, тапсырыс ID-сын және сомасын тексеру.
- Тапсырыс статусы, SQLite журналдары және әкімші кіру сессиясы.
- Payout модулі әдепкіде сөндірулі; провайдерден арнайы рұқсатсыз іске қосылмайды.
- Сервер/провайдер жоқ кезде сайт төлем жасалды деп өтірік көрсетпейді: backend қолжетімсіз екенін айтады.

## Маңызды: статикалық сайт пен нақты төлем бір нәрсе емес

Егер `dist/` папкасын жай drag-and-drop статикалық хостингке жүктесеңіз, дизайн ашылады, бірақ сервер API-і жұмыс істемейді. Netlify Functions API маршрутын қамтамасыз еткенімен, бұл нұсқада SQLite дерекқоры `/tmp` ішінде уақытша сақталады. Сондықтан код Netlify-де төлем қабылдауды, төлем статусын және әкімші журналын әдейі `503` қатесімен өшіреді: функция қайта іске қосылғанда төлем жазбасы жоғалмауы керек. Бұл жобада әлі persistent SQL дерекқор адаптері жоқ; тек `SESSION_SECRET` немесе `ADMIN_PASSWORD_HASH` қою бұл мәселені шешпейді. Төлемдерді қосу үшін тұрақты дискісі бар Node.js хостингін пайдаланыңыз немесе бөлек тұрақты дерекқор адаптерін енгізіп, нақты provider sandbox-тесттерінен өткізіңіз. Сайт ішінде құпиясөзді өзің қою формасы persistent Node.js серверге арналған.

Жобаны хостингке жүктегенде сыртқы ZIP-папкасының ішіне кіріп `index.html` іздеу мәселесі болмауы үшін архив түбірінде де `index.html`, `styles.css` және браузерлік файлдар бар. Ресми server mode-да Express қауіпсіз түрде `public/` папкасын ғана көрсетеді.

## Render арқылы backend-пен бірге жариялау

`render.yaml` және `DEPLOY-RENDER-KK.txt` қосылды. Бұл тәсіл frontend пен Node.js API-ді бір доменде іске қосып, SQLite үшін тұрақты диск қолданады. Render дискі бар сервисі ақылы жоспарды талап етуі мүмкін. Жариялау нұсқаулығын орындаңыз. Қазіргі GitHub Pages адресі тек статикалық preview болып қалады; Node.js серверін GitHub Pages іске қоспайды.

Render домені `BASE_URL` ретінде `RENDER_EXTERNAL_URL` арқылы автоматты қолданылады. Freedom Pay құпия кілттері тек хостингтің Environment Variables бөлімінде сақталуы керек.

## Локалды іске қосу

Талап: Node.js 20 немесе жаңарақ нұсқа.

1. ZIP архивін толық шығарыңыз.
2. Жоба түбірінде терминал ашыңыз.
3. `npm install` орындаңыз.
4. `.env.example` файлын `.env` деп көшіріңіз. `SESSION_SECRET` бос қалса, тұрақты Node.js хостында сервер `.session-secret` файлын өзі жасайды.
5. `npm run check`, содан кейін `npm start` орындаңыз.
6. Браузерден `http://localhost:3000/admin.html` ашыңыз. Алғашқы ретте өз логинің мен кемінде 12 таңбалы құпиясөзіңді формада өзің орнатасың; bcrypt хэшін қолмен құрастырудың қажеті жоқ.
7. Аккаунт алғаш рет орнатылған соң setup формасы қайта ашылмайды.

## Freedom Pay-ге қосу

- Мерчант аккаунтын провайдердің талаптарымен ашып, келісімін алыңыз.
- `FREEDOMPAY_MERCHANT_ID` және `FREEDOMPAY_PAYMENT_SECRET` мәндерін сервердің environment variables бөлігіне енгізіңіз. Оларды ешқашан HTML, JavaScript, GitHub немесе ашық ZIP ішіне қоймаңыз.
- Қоғамға ашық HTTPS домен үшін `BASE_URL` орнатыңыз. Провайдердегі Result URL дәл `https://your-domain.example/api/freedompay/result.php` болуы керек.
- Алдымен test режиміндегі толық циклді тексеріңіз. Провайдер берген жарамды live credentials пен келісім болмайынша live режимге ауыспаңыз.
- Live ақша ағынын қоспас бұрын Freedom Pay менеджерімен қазіргі endpoint, қолтаңба және callback параметрлерін растаңыз. Осы код осы ортада нақты провайдер credentials-пен толық end-to-end тексерілген жоқ.

## Payout туралы

`ENABLE_PAYOUTS=false` болып қалуы керек. Картаға төлем жасау үшін мерчантқа бөлек ресми payout рұқсаты, дұрыс payout secret және провайдер растаған endpoint қажет. Төлем қабылдау рұқсаты жеке картаға төлем жасау рұқсатымен бірдей емес. Бұл үлгі жеке клиенттердің ақшасын ұстап, өзара аударатын лицензияланған әмиянды алмастырмайды.

## Өндірістік қауіпсіздік

Бұл архив осы орындалу ортасында нақты Freedom Pay аккаунтымен end-to-end сыналмаған. Live төлемді дайын деп қабылдамаңыз: алдымен төлем сілтемесін жасау, қолтаңбаны тексеру, callback, қайталанатын callback және тапсырыс мәртебесін sandbox-та тексеру қажет.

- `.env` ашық жарияламаңыз; `.gitignore` оны елемейді.
- Node серверін, `DATABASE_PATH` дерекқорын және TLS/HTTPS-ті хостингте дұрыс баптаңыз. Уақытша, эфемерлік файлдық жүйе SQLite деректерін жоғалтуы мүмкін.
- `terms.html` және `privacy.html` ішіндегі `[ ... ]` placeholder-ларды нақты бизнес деректерімен толтырып, қайтарым және қолдау саясатын қосыңыз.
- Бизнес/мерчант келісімдері мен төлем функцияларына заңды түрде рұқсатты қамтамасыз етіңіз. Кәмелетке толмаған адамға аккаунт пен шарт рәсімдеу үшін заңды жауапты ересек тұлғаның қатысуы қажет болуы мүмкін.
